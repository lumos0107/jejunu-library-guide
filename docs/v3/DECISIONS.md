## 결정 사항

### D1. 방향: 할 일 중심으로 재구성 (2026-10-13)

- 지금은 이용 가이드 47 · 전자정보원 98 · 공식 메뉴 89가 한 목록에 같은 무게로 섞여 나온다. 이 구조 때문에 중복, 검색 잡음, 낯선 용어 문제가 생긴다.
- v3에서는 **학생의 할 일 하나를 카드 하나로** 보여 주고, 관련 자료와 공식 메뉴는 그 카드 안에 근거로 붙인다.
- 기존 기획(PLAN.md)의 "의도적으로 제외" 목록은 출발점일 뿐 제약이 아니다. 필요하면 바꿀 수 있다.

### D2. 배포와 운영 (2026-10-13)

- 커뮤니티에 공개 배포한다. 로그인 없이 쓴다.
- 나중에 검색 엔진 등록과 광고 게재를 고려한다.
- 로컬에서 개발하고, 마일스톤마다 커밋하고 GitHub에 push한다.
- 개발이 어느 정도 진행되면 배포 주소로도 같은 테스트를 돌린다.

### D3. 검증 도구 (2026-10-13)

- 기본: Playwright 라이브러리(Python) 테스트 스크립트. push 전에는 로컬에서, push 후에는 배포 주소에서 돌린다.
- 크로스 체크(보조): Playwright MCP, Aside MCP.
- 기존 QA-v2의 수치(234 · 98 · 89 · 47 · 학부생 45 등)를 회귀 기준으로 삼는다. 수치는 v3 구조에 맞춰 다시 정한다.

### D4. 전자정보원·공식 메뉴 보여 주기: 1안 (2026-10-13)

들어오는 길을 둘로 나눈다.

- **할 일로 들어오는 학생:** 할 일 카드 안에 "이용 방법 + 추천 자료 3~5개 + 공식 메뉴 위치"를 함께 보여 준다.
- **자료 이름을 아는 학생:** 별도 "자료 찾기" 화면에서 전자정보원 98개 전체를 분야별로 보거나 이름으로 검색한다.
- 공식 메뉴 89개는 관련된 할 일 카드에 "공식 메뉴 위치"로 붙인다. 어느 카드에도 맞지 않는 메뉴만 따로 모은다.
- 전자정보원과 공식 메뉴는 메인 목록에 같은 무게로 섞여 나오지 않는다.

검토했지만 고르지 않은 안:

- 2안: 98개를 모두 할 일 카드 안에만 넣는다. 쓸 곳이 애매한 자료를 억지로 끼워야 하고 이름으로 찾기 어려워서 제외했다.
- 3안: 지금처럼 따로 두고 이름만 쉽게 바꾼다. 중복과 잡음 문제가 남아서 제외했다.

### D5. 기술 구조: A안, 정적 사이트 유지 + 데이터 생성 스크립트 (2026-10-13)

- 빌드 도구 없이 정적 파일로 유지한다. `index.html`을 더블클릭해도 열리고(file://), GitHub Pages에 그대로 올라간다.
- 코드는 기능별 일반 스크립트 파일 몇 개로 나누고, 읽기 좋게 정리한다. ES 모듈과 JSON 파일 불러오기(fetch)는 file://에서 동작하지 않으므로 쓰지 않는다.
- 데이터는 고치기 쉬운 원본(JSON)에서 Python 스크립트가 `data.js`를 만든다.
- 테스트는 Playwright 라이브러리 방식을 그대로 쓴다.

### D6. 커밋·push 규칙 (2026-10-13)

- 작업 단위마다 로컬에서 자주 커밋한다.
- 커밋이 어느 정도 모이면 테스트(데이터 검사 + Playwright)를 돌리고, 통과하면 push한다.
- 테스트에 실패하면 push하지 않고 먼저 고친다.
- `_비공개/`에 있는 개인 기록은 커밋하지 않는다(.gitignore).

## 확장 방안 (지금은 하지 않음)

규모나 요구가 커지면 다시 검토한다.

### 기술 구조

| 안 | 내용 | 검토할 시점 |
|---|---|---|
| B. 빌드 도구 도입 (예: Vite) | ES 모듈로 나누고 배포용으로 묶는다(번들). 코드 관리가 편해지지만 수정할 때마다 빌드가 필요하고 Node 설정이 늘어난다. 더블클릭 실행은 빌드 결과물로만 가능하다 | 스크립트 파일이 많아져 연결 관리가 어려워질 때, 외부 라이브러리를 여러 개 써야 할 때 |
| C. 프레임워크 (예: React) | 화면을 컴포넌트로 다시 만든다. 이 규모에는 과하고 처음부터 다시 만들어야 한다. 검색 노출(SEO)을 위해 정적 생성 같은 추가 작업도 필요하다 | 화면이 크게 복잡해지거나 사용자별 기능(저장·동기화)이 들어갈 때 |

A에서 B로 옮길 때 다시 짜지 않도록, A안에서도 파일마다 역할을 하나씩 나누고 전역 이름을 최소로 유지한다.
