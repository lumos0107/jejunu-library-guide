### D4. 전자정보원·공식 메뉴 보여 주기: 1안 (2026-10-13)

들어오는 길을 둘로 나눈다.

- **할 일로 들어오는 학생:** 할 일 카드 안에 "이용 방법 + 추천 자료 3~5개 + 공식 메뉴 위치"를 함께 보여 준다.
- **자료 이름을 아는 학생:** 별도 "자료 찾기" 화면에서 전자정보원 98개 전체를 분야별로 보거나 이름으로 검색한다.
- 공식 메뉴 89개는 관련된 할 일 카드에 "공식 메뉴 위치"로 붙인다. 어느 카드에도 맞지 않는 메뉴만 따로 모은다.
- 전자정보원과 공식 메뉴는 메인 목록에 같은 무게로 섞여 나오지 않는다.
- **GPT 검토 반영:** 추천 자료는 3~5개로 고정하지 않고 **필요한 만큼, 기본 0~3개**로 한다. 공부 공간이나 반납 같은 카드에는 억지로 넣지 않는다.
- **GPT 검토 반영:** 카드에 붙은 공식 메뉴도 메뉴 이름으로 검색하면 그 카드와 이동 경로가 나와야 한다. 기존 자료·메뉴 이름은 계속 검색할 수 있어야 한다.
- 기존 가이드 47개를 카드 47개로 그대로 바꾸지 않는다. 대표 카드 6~10개로 구조를 먼저 검증한 뒤 나머지를 옮기고, 필요하면 합친다. 같은 서비스는 여러 카드에서 참조할 수 있다.

검토했지만 고르지 않은 안:

- 2안: 98개를 모두 할 일 카드 안에만 넣는다. 쓸 곳이 애매한 자료를 억지로 끼워야 하고 이름으로 찾기 어려워서 제외했다.
- 3안: 지금처럼 따로 두고 이름만 쉽게 바꾼다. 중복과 잡음 문제가 남아서 제외했다.

### D5. 기술 구조: A안, 정적 사이트 유지 + 데이터 생성 스크립트 (2026-10-13)

- 빌드 도구 없이 정적 파일로 유지한다. `index.html`을 더블클릭해도 열리고(file://), GitHub Pages에 그대로 올라간다.
- 코드는 기능별 일반 스크립트 파일 몇 개로 나누고, 읽기 좋게 정리한다. ES 모듈과 JSON 파일 불러오기(fetch)는 file://에서 동작하지 않으므로 쓰지 않는다.
- 데이터는 고치기 쉬운 원본(JSON)에서 Python 스크립트가 `data.js`를 만든다.
- 테스트는 Playwright 라이브러리 방식을 그대로 쓴다.
- **GPT 검토 반영:** 편집 원본은 `data/` 아래 JSON 파일(종류별)뿐이다. `data.js`는 직접 고치지 않고, 생성 결과가 원본과 일치하는지 검사한다. 스크립트 파일의 로딩 순서와 공통 전역 객체를 문서로 남긴다. 화면 코드 안의 내용 데이터(`relatedMap`, `bookCases`)도 원본으로 옮긴다. (PRD 2차 검토에서 "JSON 하나"를 "단일 원천, 파일은 종류별"로 명확히 함)

### D6. 커밋·push 규칙 (2026-10-13)

- 작업 단위마다 로컬에서 자주 커밋한다.
- 커밋이 어느 정도 모이면 테스트(데이터 검사 + Playwright)를 돌리고, 통과하면 push한다.
- 테스트에 실패하면 push하지 않고 먼저 고친다.
- `_비공개/`에 있는 개인 기록은 커밋하지 않는다(.gitignore).
- **GPT 검토 반영:** push 직전 검사 순서를 고정한다: 데이터 생성 → 데이터 검사 → Playwright 테스트 → `_비공개/` 제외 확인. 공식 사이트 쪽 장애(예: 원래 끊긴 첨부 링크)는 경고로 처리해 우리 코드의 실패와 구분한다.

### D16. PRD v1.1 문구 정리 (2026-10-13, 3차 교차 평가 합의)

범위·기준은 바꾸지 않고, 리서치에서 드러난 모호한 문구만 정리했다. 근거는 [REVIEW-2026-10-13-3.md](REVIEW-2026-10-13-3.md).

- **① 보조 필드:** `facts`에 선택 값 `kind`(`location`·`auth`·`hours`)를 둔다. 상세에서 위치·인증 요약·시간을 제자리에 보여 주기 위함이다. 목록형 가이드에는 `findHint`를 둔다. 둘 다 부록 E 전환표로 ②의 구조 필드에 옮긴다(R24).
- **로컬 검사 주소:** 로컬 자동 검사는 `http://127.0.0.1` 서버로 한다. 브라우저가 127.0.0.1을 https와 같은 안전한 환경으로 취급하고, 이 사이트는 정적 파일만 쓰므로 로컬 인증서를 만들 이유가 없다. https는 배포 주소에서 검사한다(R16).
- **배포 버전 확인:** 파일 안에 버전 표식을 넣지 않고, 배포된 파일과 push한 커밋의 파일 해시를 비교한다. 생성물 검사(`git diff --exit-code data.js`)와 충돌하지 않는다(R23).
- **push 게이트:** 첫 단계에서 작업 트리가 깨끗한지(`git status --porcelain`이 비어 있음) 확인한다. 테스트한 파일이 push할 커밋과 같다는 2장 9번 조건을 기계적으로 보장하기 위함이다(R18).

### D17. 시설 카드의 공식 링크를 개별 시설 페이지로 (2026-10-13, 4차 교차 평가 합의)

- `group`·`maker`·`carrel`·`seat`의 공식 링크를 시설 메뉴 첫 화면(`#/service/facility`, 실제 도착은 "전체" 탭)에서 개별 페이지(`studyroom`·`makerstudio`·`carrel`·`readingroom`)로 바꾼다.
- 이유: 사실 확인에 쓴 페이지와 버튼의 도착지가 같아지고, 학생이 "전체" 탭에서 다시 찾는 한 걸음이 사라진다. 네 주소 모두 새 문서로 열었을 때 제목이 맞는 페이지로 바로 도착함을 확인했다.
- 따라서 PRD 부록 A의 A1 요청 주소를 `#/service/facility/studyroom`으로 바꾼다. 근거는 [REVIEW-2026-10-13-4.md](REVIEW-2026-10-13-4.md) 4장.

### D18. 전자정보원 카드의 찾는 방법: 가나다·ABC 버튼 + 실제로 찾아지는 검색어 (2026-10-13, 배포 뒤 사용자 질문·GPT 상의)

- 공식 전자정보원 목록은 '카' 버튼이나 검색으로 거른 상태를 주소에 담지 않고, 주소 값도 읽지 않는다. 통합검색은 전자정보원을 찾지 않는다. 그래서 걸러진 목록으로 바로 보내는 주소는 만들 수 없다(official_facts 11장).
- 공식 버튼은 그대로 목록으로 보내고, 찾는 방법을 "공식 목록의 가나다·ABC 줄에서 '카' 버튼을 누르세요. 또는 목록 위쪽의 검색 칸에 '카피킬러'를 입력하세요."로 바꾼다. 버튼 글자는 공식 거르기와 같은 규칙으로 이름에서 계산한다(된소리 초성은 버튼 문장을 뺀다). 전자책 목록은 가나다 줄이 없어 검색 칸만 안내한다.
- 공식 이름과 띄어쓰기·Trial 표기가 달라 우리 이름으로는 0건이던 6개에 `findTerm`(이름 안의 말)을 둔다. 카드마다 문장을 저장하는 `findHint`는 예외용으로만 쓴다.
- 공식 이름·버튼 구성이 바뀔 수 있으므로 `tests/check_er_find.py`로 링크 점검과 함께 월 1회 대조한다. 공식 페이지 구조가 바뀌어 점검할 수 없을 때는 카드 오류로 단정하지 않는다.
- 공식 개별 안내 페이지가 있는 자료(예: 카피킬러)는 그 페이지를 관련 링크로 함께 준다(5550bfd).

### D19. 공식 홈 하단 기관 로고 배너를 공식 메뉴 카드로 (2026-10-13, 배포 뒤 사용자 질문·GPT 상의)

- 공식 홈 맨 아래 로고 배너 6곳 중 5곳(RISS·한국학술지인용색인·ScienceON·국립중앙도서관·국회도서관)을 공식 메뉴 카드(분류 "공식 홈 하단 배너")로 추가한다. 사이트 이름으로 검색하면 바로 나오고, "공식 홈페이지에서는 어디에 있나요?"에 답하는 메뉴 카드의 역할과 같다. dCollection은 이미 메뉴 카드(menu-031)가 있어 단계에 배너 경로만 더한다.
- 공식 홈에는 이 줄의 제목이 없어서 "관련 사이트" 같은 이름을 공식 명칭처럼 쓰지 않는다. 버튼은 도착지가 외부 사이트임이 드러나게 "외부 사이트 열기"로 한다.
- RISS는 배너와 같은 교외접속(openlink) 경로를 https로 쓴다(학교망에서 도착 확인). 학교 밖 화면은 확인하지 못했다고 카드에 적고, 교외접속·원문복사 안내를 함께 연결한다.
- 사이트 소개(각 사이트의 자기 설명)는 외부 출처라 넣지 않는다. 이용 조건은 "그 사이트 안내를 확인"으로 둔다. 할 일 중심의 설명(예: 다른 학교 학위논문 찾기)은 ② 카드 통합 때 확인한 범위에서 붙인다.

### D20. 공식 사이트 전체 점검 반영 (2026-10-13, 사용자 요청·GPT 상의)

- 공식 사이트 243화면을 열고 눌러 본 결과([research/site_audit_2026-10-13.md](research/site_audit_2026-10-13.md))를 반영한다. 새 화면 수보다 학생이 실제로 할 수 있게 되는 일을 기준으로 한다.
- 지금(①): 장소·절차·조건이 빠진 기존 카드를 먼저 보완한다(노트북 사용 가능 구역, 상호대차 탭과 대출기간 불일치 표시, iThenticate 요청 방법, 교육일정·교육자료·온라인 이용교육·학술공지, 신입생 온라인 이용교육 조건, 앱 좌석배정·대출 사용법, 분관 이용시간·분관 사이트, 영문 홈페이지, 오시는 길, 이용지침).
- 국회·국립중앙도서관 원문 이용(지정 PC)은 방문 장소와 이용 방식이 중요한 독립된 할 일이라 새 할 일 안내 카드로 만들고, 기관 로고 배너 카드·원문복사 카드에서 연결한다. 원문복사(우편 복사 의뢰)와 섞지 않는다.
- 독서주간(10.16까지)은 '지금 이 시기' 공지로 넣고, 독서주간 한정인 대출 정지 해제를 앞세운다. 기념품이 남아 있다고 단정하지 않는다.
- 보류: BK21 '전지적 논문시점'(본문이 포스터 이미지라 대상 미확인). ②: "책·논문 검색하는 법" 할 일 카드를 먼저, 그다음 읽을거리·이용자별 안내, 도서관 소개 묶음은 뒤로.

### D21. 디자인 시안 v1: 색 5개·Pretendard 서브셋·첫 화면 정리 (2026-10-13, 6차 교차 평가, 사용자 확인 대기)

- 첫 화면: 검색(맨 위, D11 유지) → '지금 이 시기' 한 줄(1건부터 접기) → 짧은 소개 → 상황 6개(정적 HTML) → 예시.

### 그 밖의 GPT 검토 반영 (2026-10-13)

- 확인 날짜는 운영시간·요금·대상·시범기간처럼 자주 바뀌는 정보부터 출처와 함께 붙인다. 모든 레코드에 같은 날짜를 일괄로 넣지 않는다.
- 기간이 끝난 서비스는 숨기지 않고 "시범기간 종료·현재 제공 여부 미확인"으로 표시한다. 연도를 모르는 기간(CAS 등)은 만료일을 추측해서 넣지 않는다. 날짜가 지나면 사라지는 것은 "지금 이 시기" 공지뿐이다.
- 검색 결과가 0건이면 먼저 검증된 동의어와 전체 범위 재검색을 제공한다. 0건이라고 해서 도서관이 그 서비스를 제공한다고 추측하지 않는다.
- 일반 면책 문구는 한 번만 둔다. 비용·대상·인증 예외처럼 이용 결정에 필요한 조건은 그대로 보여 준다.
- 빠졌던 것을 범위에 넣는다: 책 반납 안내, 이용 단계의 "…확인"을 실제 행동으로 바꾸기(대표 과업부터), 적용 중인 필터를 결과 위에 보여 주고 하나씩 해제, 상황 탭을 눌러도 검색어 유지.
- 상의 기록 원문: `_비공개/GPT_상의_기록.md` (git 제외).
