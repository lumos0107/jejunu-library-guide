# 공식 링크 전체 점검 (2026-10-14)

사용자: "공식 안내 열기들의 주소가 설명과 좀 다른 것들이 있는 듯, 다 점검해."

## 방법

- 사이트의 모든 공식 링크 484개(고유 주소 272개)를 열었다: 카드 버튼(`source`), 아래 참고 자료(`materials`), 사실 출처(`facts.source`). 공식 도서관 화면은 10/13 사이트 점검 수집기와 같은 방법(내용이 멈출 때까지 기다린 뒤 경로·제목·본문을 읽음)으로 읽었다.
- 도착 화면의 경로(Home › …)·제목·본문에 카드 이름(메뉴 카드는 설명 경로의 마지막 메뉴 이름)이 있는지 비교하고, 다른 화면으로 넘어가거나 내용이 없거나 열리지 않는 것을 골라 하나씩 봤다.
- 전자정보원 매뉴얼 140여 개는 파일이 실제로 내려받아지는지 확인하고, 공식 목록 API(`pyxis-api/1/er-sources`)의 자료별 링크와 하나하나 대조했다.
- **범위:** 이번 점검은 링크가 열리는지, 어느 화면에 도착하는지, 그 화면 이름이 카드와 맞는지까지다. 카드의 사실(facts) 문장을 본문과 대조한 것은 10/13 사이트 전체 점검(D20) 당시 기록이며, 지금 내용 전체의 정확성을 보증하지 않는다. 매뉴얼 파일 안의 제품명·버전도 열어 보지 않았다.

문제 없음으로 본 것:

- 나머지 이용 가이드 버튼 45개는 카드 이름과 같은 공식 화면에 도착했다. '책 반납하기'는 공식 화면의 경로 표시가 '대출/연장/예약'으로 남지만 내용은 '반납/연체/변상' 탭이라 맞다. '모바일 도서관 앱'·'대출·연장·예약'처럼 상위 주소가 첫 하위 화면으로 넘어가는 것은 공식 사이트의 기본 동작이다.
- My Library 메뉴 17개는 로그인 화면까지 확인했다(개인 메뉴. 로그인 이후 해당 메뉴로 이어지는지는 확인하지 않음).
- 전자정보원 매뉴얼은 위 er-069 하나를 빼고 모두 내려받아지고, 공식 목록의 자료별 링크와 같다(카드에 일부러 더한 도서관 안내 화면 링크 2개 제외). CAS 4종은 공식 API 이름에 'Trial'이 없지만 시범서비스 표시(isTrial)가 있어 지금 카드 이름·찾는 말(D18)이 맞다.
- 전자정보원 찾는 방법(`tests/check_er_find.py`): 96/96 통과(Endnote Fusion 포함).

## 버튼 이름 규칙(GPT 2라운드 합의)

- 여러 화면을 다루는 카드는 큰 버튼이 어디로 가는지 이름으로 말한다(`sourceLabel`, 가이드·메뉴 카드, 20자 안의 "… 열기", 데이터 검사가 확인). 카드를 나누지 않는 이유: 나머지 화면은 상세 아래 이름 붙은 자료 링크로 있고, 나누면 같은 질문에서 카드 여러 개를 비교해야 한다.
- 버튼 주소가 전자정보원·전자책 목록이면 가이드 카드도 '공식 전자정보원 목록 열기'처럼 목록이라고 말한다(지금까지는 자료 카드만).
