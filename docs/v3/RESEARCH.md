## 2. 현재 코드 구조 요약

- **로딩:** `data.js` → `app.js` 순서이고 둘 다 `defer`로 실행된다. 전역은 `window.LIBRARY_GUIDE` 하나이고, app.js는 IIFE라 전역을 만들지 않는다.
- **data.js 형식:** 접두어 + `json.dumps(obj, ensure_ascii=False, indent=2)` + `;\n`이 원본과 **바이트 단위로 같다**. 그래서 P1-03의 생성·`--check`를 바로 구현할 수 있다.
- **검색(app.js L15):**
  - 필드 10개(name, question, description, officialDescription, keywords, caution, subject, sourceType, menuGroup, menuSubgroup)와 steps를 이어 붙인 뒤 공백을 지우고 부분 문자열로 비교한다.
  - 정렬은 없다.
  - `filter(Boolean)`이 정규화보다 먼저라서 기호만 입력하면 234건이 나온다.
- **상태:** `state` 객체 하나다.
  - app.js는 `history`·`location`·`hash`를 한 번도 쓰지 않는다. 다만 index.html의 문서 앵커 링크(`#top`, `#situations`, `#services`)를 누르면 주소의 hash는 바뀐다. 헤더의 자료 링크는 app.js가 `preventDefault`로 막는다.
  - `changeScope`는 상황 필터만 초기화한다.
  - 상황 탭을 누르면 검색어가 지워진다(L38).
- **상세:** `openDetail`이 대화상자를 그린다. 공식 버튼은 **맨 끝**에 있고, 면책 문구가 가이드에 2개, 자료에 4개 나온다.
- **내용 데이터가 코드 안에 있음:** `relatedMap`(L28, 키 32개)과 `bookCases`(L37)는 IIFE 안의 JS 상수다. Node `vm`으로 추출할 수 있다(실측 성공).
- **CSS:**
  - 3줄 압축이다. 중복 정의가 6곳 있다(`.result-heading` 등).
  - 대비는 muted 4.48·4.31, 포커스 링 2.58로 기준에 못 미친다.
  - 560px 이하에서는 nav가 '공식 도서관' 하나만 남는다.
- **DOM 계약:** `#search-input`을 L21·38·39에서 직접 참조한다. 모바일 상단에 입력창을 복제하면 id가 겹치므로, **입력창 하나를 위치만 옮기는 방식**이 안전하다.

## 5. ① 콘텐츠 수정에 쓸 공식 사실 (2026-10-13 확인)

원칙:
- **사실 하나에 출처 하나.** 모든 수정 사실은 `facts: [{kind?, text, source, checkedAt}]`로 붙이고, `source`는 그 사실을 적은 공식 페이지다(R5). `kind`는 화면 위치를 정하는 선택 값이다: `location`(위치), `auth`(인증·로그인 예외), `hours`(시간). 없으면 "확인한 사실" 목록에 나온다(R24, D16).
- **대상·비용 요약**은 `eligibilityNote`·`costNote`(P1-07)에 짧게 쓰고, 근거는 같은 레코드의 `facts`에 둔다.
- **`audience`는 바꾸지 않는다.** v2의 `audience`는 학부/대학원 필터용 값이라 ①에서 바꾸면 필터 결과가 달라진다. 실제 이용 자격은 `eligibilityNote`로만 보여 준다(R10).
- **확인하지 못한 것은 쓰지 않거나 "확인하지 못함"으로 쓴다.** 2018년 FAQ에만 있는 내용, 이미지로만 된 공지(야간버스표, FAQ 665 표, 공지 6648·6490)는 단정하지 않는다.

## 8. PLAN에 넘길 결정

- **상세 방식(PRD 10장 열린 질문):** ①은 v2의 대화상자를 유지한다(D15). ②의 방식은 ② 계획에서 정한다.
- **불용어 vs 키워드 보강:** ②에서 정한다. ①은 키워드 보강만 한다(4장 4번).
- **WebKit 설치:** ① 작업 시작 전에 한다.
- **커밋 단위:** P1 항목 하나가 커밋 하나 이상. 테스트 → 구현 → 테스트 통과 순서.
- **PRD 문구 정리(D16):** `facts.kind`·`findHint` 보조 필드, 로컬 검사 주소 `http://127.0.0.1`, 배포 버전 확인 = 파일 해시 비교, 게이트의 작업 트리 확인.
