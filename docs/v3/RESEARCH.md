## 2. 현재 코드 구조 요약

- **로딩:** `data.js` → `app.js` 순서이고 둘 다 `defer`로 실행된다. 전역은 `window.LIBRARY_GUIDE` 하나이고, app.js는 IIFE라 전역을 만들지 않는다.
- **data.js 형식:** 접두어 + `json.dumps(obj, ensure_ascii=False, indent=2)` + `;\n`이 원본과 **바이트 단위로 같다**. 그래서 P1-03의 생성·`--check`를 바로 구현할 수 있다.
- **검색(app.js L15):**
  - 필드 11개와 steps를 이어 붙인 뒤 공백을 지우고 부분 문자열로 비교한다.
  - 정렬은 없다.
  - `filter(Boolean)`이 정규화보다 먼저라서 기호만 입력하면 234건이 나온다.
- **상태:** `state` 객체 하나다. 주소(history·hash)는 쓰지 않는다.
  - `changeScope`는 상황 필터만 초기화한다.
  - 상황 탭을 누르면 검색어가 지워진다(L38).
- **상세:** `openDetail`이 대화상자를 그린다. 공식 버튼은 **맨 끝**에 있고, 면책 문구가 가이드에 2개, 자료에 4개 나온다.
- **내용 데이터가 코드 안에 있음:** `relatedMap`(L28, 키 32개)과 `bookCases`(L37)는 IIFE 안의 JS 상수다. Node `vm`으로 추출할 수 있다(실측 성공).
- **CSS:**
  - 3줄 압축이다. 중복 정의가 6곳 있다(`.result-heading` 등).
  - 대비는 muted 4.48·4.31, 포커스 링 2.58로 기준에 못 미친다.
  - 560px 이하에서는 nav가 '공식 도서관' 하나만 남는다.
- **DOM 계약:** `#search-input`을 L21·38·39에서 직접 참조한다. 모바일 상단에 입력창을 복제하면 id가 겹치므로, **입력창 하나를 위치만 옮기는 방식**이 안전하다.

## 7. 구현 위험과 대응

| 위험 | 근거 | 대응 |
|---|---|---|
| 파일을 나누면 IIFE 지역 변수를 공유할 수 없음 | app.js 구조 | 공용 네임스페이스 하나(`window.LG`)와 로딩 순서를 문서화. 데이터 전역 `window.LIBRARY_GUIDE`는 그대로 |
