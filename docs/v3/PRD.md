## 1. 목적

제주대학교 학생이 도서관 서비스 이름을 몰라도 **지금 하려는 일**에서 출발해 쓸 수 있는 서비스를 찾고, 이용 조건을 이해한 뒤, 공식 서비스로 정확하게 이동하게 한다.

### 대상

1. 도서관을 거의 안 써 본 학부생
2. 과제·발표 자료를 찾는 학부생
3. 논문을 쓰는 대학원생
4. 자료 이름(예: JSTOR)을 이미 알고 쓰는 곳만 찾는 학생

### 성공 기준

| # | 기준 | 판정 방법 |
|---|---|---|

- **도움:** 진행자가 화면 위치, 용어 뜻, 누를 곳을 알려 주는 것
- **핵심 막힘:** 잘못된 서비스 선택, 이용 조건 오해(대상·비용·인증), 공식 이동 실패. 발견하면 수정하고 같은 과업으로 다시 확인한다. 해결되지 않으면 커뮤니티 공개를 보류한다
- **조건 이해(S8에 포함):** 과업이 끝난 뒤 "이 서비스를 누가, 얼마에, 어떻게 인증해서 쓸 수 있나"를 묻고 답이 맞는지 기록한다

## 2. 바꾸면 안 되는 조건 (범위 제한)

1. **로그인·회원가입·개인정보 수집이 없다.** 사이트 안 입력은 검색어뿐이다. 오류 제보는 외부 구글 폼으로만 받는다(D9).
2. **비공식 사이트임을 숨기지 않는다.** 학교 로고나 공식 사이트로 착각할 만한 표현을 쓰지 않는다. 실제 이용은 언제나 공식 서비스로 보낸다.
3. **확인하지 않은 사실을 단정하지 않는다.** 무료, 이용 가능, 구독 중, 만료일을 추측해서 쓰지 않는다. 다시 확인하려 했는데 확인하지 못한 것은 "미확인"이라고 쓴다.
4. **대출·예약·신청을 대신하지 않는다.** 실시간 좌석이나 운영 상태를 보여 주는 척하지 않는다.
5. **정적 사이트를 유지한다(D5).** 빌드 도구·프레임워크·ES 모듈·fetch를 쓰지 않는다. 일반 `<script>` 파일만 쓴다.
   - file://과 배포 주소에서 공통으로 보장하는 것: 검색, 필터, 상세 열기.
   - **주소(#) 상태 복원과 뒤로가기는 ②부터 보장한다(D7, D15).**
   - 공유 링크는 배포 주소 기준으로 만든다. file://에서 열었더라도 "링크 복사"는 배포 주소 + # 상태를 준다.
6. **편집 원본은 `data/` 아래 JSON 파일(종류별)뿐이다.** `data.js`는 생성 결과물이며 직접 고치지 않는다. 화면 코드 안의 내용 데이터(`relatedMap`, `bookCases`)도 원본으로 옮긴다.
7. **자료와 메뉴를 잃지 않는다.** 기존 전자정보원 98개·공식 메뉴 89개는 ID 기준으로 모두 어딘가에서 찾을 수 있어야 한다. 가이드(v2의 47개 + ①에서 추가한 가이드)는 이전·통합·삭제 내역을 이유와 함께 남긴다. 틀린 정보와 중복 문구까지 남기라는 뜻은 아니다.
8. **`_비공개/`는 커밋하지 않는다.**
9. **push 전에는 검사 순서를 통과한다(D6).** 데이터 생성 → 데이터 검사 → Playwright 테스트 → `_비공개/` 제외 확인. 배포를 시작한 뒤에는 push할 때마다 **배포본이 방금 push한 버전인지 확인한 다음** 배포 주소에서도 테스트를 돌린다.
10. **데이터와 주소(#) 값을 모두 믿지 않는다.** 화면에 넣는 값은 이스케이프하고, 주소에서 온 id·필터·검색어는 허용 목록과 존재 여부를 확인한 뒤에만 쓴다. 링크는 https만 연다.

## 3. 범위와 단계 (D7)

### ① 공개 전 필수 → 끝나면 조용히 배포

①은 **지금 데이터 구조를 유지한 채** 틀린 정보와 불편을 고친다. 데이터 모델 전환은 ②에서 한다.
JSON 추출을 ①에 둔 이유: ①에서 데이터를 고쳐야 하는데, 생성물(data.js)을 직접 고친 뒤 나중에 옮기면 같은 수정을 두 번 하게 되고 2장 6번과도 어긋난다. 그래서 **구조는 바꾸지 않고 옮기기만** 한다.

## 4. 화면과 주소 (D11)

| 화면 | 주소 | 내용 |
|---|---|---|
| 홈 | `#/` | 짧은 소개, 맨 위 검색창, "지금 이 시기" 공지(있을 때만), 상황 분류 6개, 대표 할 일 카드 |
| 상황별 카드 | `#/category/<id>?level=…` | 고른 상황의 할 일 카드 목록 |
| 검색 결과 | `#/search?q=…&cat=…&level=…` | 구획: 할 일 / 자료 / 공식 바로가기. 적용 중인 필터 표시와 해제. 0건 처리 |
| 할 일 상세 | `#/task/<id>` | 공식 버튼 → 이용 조건(핵심·예외) → 위치(있을 때) → 이용 방법 → 필요한 자료 → 공식 사이트에서 찾는 곳 → 관련 할 일 → 출처·확인일 |
| 자료 찾기 | `#/resources?q=…&subject=…&status=…` | 98개, 분야·이용 상태 필터, 이름 검색 |
| 자료 상세 | `#/resource/<id>` | 공식 설명, 매뉴얼 링크, 붙은 할 일, 공식 목록에서 찾는 방법 |
| 공식 바로가기 | `#/menus?group=…` | 카드에 안 붙은 메뉴를 분류별로, 카드에 붙은 메뉴는 해당 카드로 안내 |

**주소 값 규칙**

- 파라미터마다 허용값 목록이 있다. 기본값은 주소에서 생략한다.
- 모르는 파라미터나 허용 밖 값은 무시하고, 주소를 정리해 replace한다.
- 모르는 id는 그 종류의 목록 화면으로 보내고 "찾을 수 없는 안내" 문구를 보여 준다.
- 합쳐진 가이드의 옛 id는 이전 내역을 따라 새 카드로 replace한다. 삭제된 id는 이유와 함께 안내한다.

**기록과 뒤로가기 규칙 (H7)**

- 사이트 안에서 화면이 바뀌면 기록을 남긴다(push).
- 검색: 검색 화면에 들어가는 첫 입력만 기록하고, 이후 입력은 주소만 갱신한다(replace, 짧은 지연 후).
- 사이트 안에서 연 상세를 닫으면 바로 전 상태로 돌아간다(history.back).
- 공유 링크로 바로 들어온 상세를 닫으면 그 종류의 목록 화면으로 replace한다(할 일 → 홈, 자료 → 자료 찾기, 메뉴 → 공식 바로가기).
- 브라우저 뒤로가기는 기본 기록을 따른다(직접 들어왔다면 사이트 밖으로 나가도 정상).
- 상세를 대화상자로 둘지 별도 화면으로 바꿀지는 PLAN에서 정하되, 위 규칙은 어느 쪽이든 지킨다.

**그 밖의 화면 규칙**

- 모바일: 검색과 주요 메뉴가 위에 계속 보인다. 카드는 한 열. 누르는 영역 44px 이상.
- 화면 문구는 부록 D 용어표를 따른다.
- 나중에 카드별 정적 페이지를 만들 때 `#/task/<id>`를 `/task/<id>.html`로 옮길 수 있게 id는 영문 소문자·숫자·하이픈만 쓴다(D10).

| 편집하는 쪽 | 생성되는 반대쪽 |

| `task.resources` (추천 자료 0~3개) | `resource.usedIn` (붙은 할 일) |

### 할 일 카드 (task)

| 필드 | 설명 |
|---|---|
| `id` | 영문 소문자·숫자·하이픈. 기존 가이드 id를 되도록 유지 |
| `title` | 행동형 제목 ("팀플할 공간 예약하기") |
| `question` | 학생 말투 질문 |
| `category` | 상황 분류 6개 중 하나 |
| `levels` | 학부/대학원 필터용. `["undergrad","grad"]` 중 해당하는 것. 기본은 둘 다 |
| `eligibility` | 이용 자격 목록. 각 항목 `{anyOf: [code…], text, source, checkedAt}`. **항목 안의 code는 하나만 맞으면 되고(OR), 항목끼리는 모두 충족해야 한다(AND).** 예: 그룹스터디룸 = `[{anyOf:["enrolled","staff"], text:"재학생·교직원"}]`. code 예: `enrolled`(재학생), `staff`, `disabled`, `member`(도서관 회원). 비어 있으면 "자격 제한 정보 없음 — 공식 안내 확인" |
| `cost` | `{type, text, source, checkedAt}`. type: `free`(무료가 공식 안내로 확인됨) / `paid` / `partial`(일부 유료·지원 한도) / `unknown` |
| `conditions` | 그 밖의 변동 사실 `{text, source, checkedAt, validFrom?, validTo?}` |
| `location` | `{text, source, checkedAt}`. 공간·기기 서비스만. 출처가 없으면 넣지 않음 |
| `summary` | 목록 카드의 짧은 설명 |
| `steps` | `{text, verified, sourceRef}`. verified: `public`(공개 안내로 확인) / `unverified-login`(로그인 뒤 화면 미확인). `public` 단계는 `sourceRef` 필수 |
| `official` | 대표 공식 링크 `{label, url, kind}`. kind: `page`(해당 페이지) / `list`(목록 첫 화면 — 찾는 방법을 함께 표시) |
| `keywords` | 검색용 단어(공통 주의 문구 넣지 않음) |
| `featured` | 홈 대표 카드 여부 |
| `reviewedAt` | 카드 전체를 마지막으로 검토한 날짜(상세 맨 아래 표시). 개별 변동 사실은 각자의 `checkedAt`을 옆에 표시 |

### 자료 (resource)

- 현재 필드를 유지한다. 98개에 공통인 주의·단계 문구는 화면 상수로 옮기고 검색 대상에서 뺀다.
- `aliases`: 검증된 약칭·한글 표기·공식 원문 표기(예: "JSTOR Collection" → "JSTOR", "제이스토어"; 공식 원문 오타 "Sage Premire" → 바른 철자). 정확 이름 일치에 쓴다. 다른 자료·메뉴의 이름이나 별칭과 겹치면 데이터 검사 오류.
- `status` (값마다 필수 필드가 있다):

| 값 | 뜻 | 필수 필드 |
|---|---|---|
| `listed` | 목록에 등재(이용 범위 확인 필요) | — |
| `open` | 공개자료로 안내 | — |
| `trial` | 시범서비스, 기간이 연·월·일까지 확인됨 | `trialFrom`, `trialTo` |
| `trial-period-unclear` | 시범서비스, 기간 표기에 연도가 없는 등 확인 불가 | `trialPeriodText`(원문). 날짜를 추측하지 않는다 |
| `ended` | 출처로 종료가 확인됨 | `endedSource` |

- 화면: `trial`은 `trialTo`가 지나면 "시범기간 종료 — 현재 제공 여부 미확인"으로 표시한다. 자료는 숨기지 않는다.
- `accessType`: `status`와 의미를 대조해, 겹치면 status에서 만들어 내고 편집 원본에서는 뺀다(P2-01).
- `useFor`: "과제에서 이렇게 쓴다" 한 줄. ②에서는 대표 카드에 붙는 자료부터 채운다.

### 공식 메뉴 (menu)

현재 필드를 유지하고 `aliases`(선택)와 생성되는 `attachedTo`를 더한다. 89개에 공통인 질문·주의 문구는 화면 상수로 옮긴다.

### 공지 (notice)

`{id, text, link, source, checkedAt, startsOn, endsOn, taskIds}`. `taskIds`의 카드가 실제로 있는지 데이터 검사로 확인한다.

### 날짜 규칙

- 저장 형식은 `YYYY-MM-DD`이다.
- 기준은 **보는 사람 기기의 오늘 날짜**이고, 시작일과 종료일 당일을 포함한다. 문자열 비교로 판정한다. `new Date('YYYY-MM-DD')`는 UTC로 해석되므로 쓰지 않는다.
- 테스트는 날짜를 고정해서 돌린다(Playwright 시계 고정).
- 데이터 검사: 날짜 형식, 시작일 ≤ 종료일, 상태별 필수 필드.

### 동의어 (synonyms)

- 저장 방식: `[["조별과제","팀플","팀프로젝트","조모임"], ["프린터","프린트","인쇄"], …]`처럼 **같은 뜻 묶음**으로 저장한다. 묶음 안에서는 양방향이다.
- 여러 단어로 된 동의어는 공백을 지운 형태로 저장한다.
- 한 단어가 여러 묶음에 들어가면 데이터 검사 오류로 처리한다.
- 검증된 묶음만 넣는다. 0건이 나온 검색어라고 해서 도서관이 그 서비스를 제공한다고 가정하고 추가하지 않는다.

### "무료" 처리

- 비용 설명 문장은 검색 대상에서 뺀다.
- `cost.type`이 `free`인 카드에만 생성 스크립트가 검색어 "무료"를 붙인다. "무료"라는 단어는 이 생성 키워드로만 일치한다.
- 데이터 검사는 **편집 원본 JSON**을 대상으로 한다. 원본의 검색 대상 필드에는 `cost.type`과 관계없이 "무료·무제한"이 있으면 안 된다. 생성 키워드는 원본에 없으므로 이 규칙과 충돌하지 않는다.

## 6. 검색 규칙

| 순서 | 규칙 | 단계 |
|---|---|---|
| 1 | **단어 나누기:** 검색어를 공백으로 나눈다 | ① |
| 2 | **정규화(단어마다):** NFKC → 소문자 → 공백·문장부호·기호 제거. 비교 대상 필드도 같은 방식으로 정규화한다("영어논문" = "영어 논문") | ① |
| 3 | **빈 단어 처리:** 정규화 뒤 빈 단어는 버린다. 모든 단어가 비면 결과 대신 "검색어를 입력하세요" 안내를 보여 준다 | ① |
| 4 | **결합:** 모든 단어가 맞아야 결과에 나온다(AND). 단어마다 필드를 하나씩 따로 비교하고, 필드를 이어 붙여 비교하지 않는다. 단어끼리는 서로 다른 필드에서 맞아도 된다 | ① |
| 5 | **동의어:** 단어마다 그 단어가 속한 동의어 묶음 전체를 후보로 삼아, 하나라도 맞으면 일치(OR). 이어지는 단어들을 붙인 형태가 동의어와 같으면 한 단위로 묶고, 겹치면 더 긴 묶음을 먼저 쓴다(예: "팀 프로젝트 공간" → [팀프로젝트][공간]) | ② |
| 6 | **엄격 AND 보완:** "할·곳·찾기" 같은 말 때문에 0건이 되지 않게, 제한된 불용어 목록(데이터) 또는 질문·키워드·동의어 보강 중 하나를 PLAN에서 골라 검색어 표로 검증한다 | ② |
| 7 | **점수:** 아래 검색 필드 표의 가중치. 단어마다 가장 잘 맞은 필드의 가중치를 더한다. 검색어 전체가 자료·메뉴의 이름 또는 별칭과 정확히 같으면 +100 | ② (①은 최소 정렬: 이름·제목에 검색어가 있으면 먼저) |
| 8 | **구획과 순서:** 할 일 / 자료 / 공식 바로가기. 정확한 이름·별칭 일치가 있는 구획을 맨 앞에, 없으면 할 일 구획이 맨 앞. 구획 안에서는 점수 → 대표 카드 → 제목 순 | ② |
| 9 | **같은 서비스 묶기:** 카드에 붙은 메뉴(`task.menus`)와 `task.represents`의 자료·메뉴가 일치하면, 따로 보이지 않고 그 카드 안에 "일치: 자료/공식 메뉴 '…'"로 보인다. 검색어가 그 이름·별칭과 정확히 같으면 자료·공식 바로가기 구획에도 보인다. 같은 레코드는 한 번만 보인다. 링크 주소가 같다는 이유로 합치지 않는다 | ② |
| 10 | **0건 처리:** ① 필터가 걸려 있으면 "필터를 풀면 N건"과 해제 버튼. ② 그래도 0건이면 일부 단어만 맞는 결과를 "일부 단어 일치"로(일치한 단어 수 → 점수 순) 보여 주고, **맞지 않은 단어를 위에 표시**한다(예: "'무료'는 일치하지 않음"). ③ 그래도 0건이면 이유 안내, 공식 문의 링크, 제보 링크(검색어 미리 채움). 도서관에 없는 서비스를 지어내지 않는다 | ①(필터 안내·제보 링크), ②(일부 일치) |

## 부록 E. 필드 전환표 (① → ②)

| ① 필드 | ② 필드 | 규칙 |
|---|---|---|
| `facts[]` | `conditions[]` 또는 `eligibility`·`cost`·`location` | 출처·확인일을 그대로 옮김. 옮긴 뒤 ① 필드 제거 |

| `audience`(all/grad) | `levels` | grad → `["grad"]`, all → 둘 다 |
| `accessType` | `status`에서 생성 | 의미 대조 뒤 결정 |
| `caution`(고유 부분) | `conditions[]` | 공통 문구는 화면 상수로 |
| `channel`·`login` | `steps`·`eligibility` | 값 표기 통일 |
