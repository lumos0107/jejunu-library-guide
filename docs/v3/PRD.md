## 1. 목적

제주대학교 학생이 도서관 서비스 이름을 몰라도 **지금 하려는 일**에서 출발해 쓸 수 있는 서비스를 찾고, 이용 조건을 이해한 뒤, 공식 서비스로 정확하게 이동하게 한다.

### 대상

1. 도서관을 거의 안 써 본 학부생
2. 과제·발표 자료를 찾는 학부생
3. 논문을 쓰는 대학원생
4. 자료 이름(예: JSTOR)을 이미 알고 쓰는 곳만 찾는 학생

### 성공 기준

| # | 기준 | 판정 방법 |
|---|---|---|
| S1 | **대표 과업**(부록 A)을 부록 A의 시작 상태에서 시작해 과업별 행동 한도 안에 끝낸다. 행동 = 클릭 1회 또는 검색어 입력·제출 1회. 끝 = 정답 상세에서 공식 버튼을 누름 | **통과 = 세 가지 모두:** ① 정답 상세 ID ② 요청 주소(버튼 href, 새 탭의 첫 주소)가 부록 A와 `#` 뒤까지 포함한 전체 주소로 같음 ③ 목록형 링크면 찾는 방법(`official.findHint`)이 보임. 도착 상태는 부록 A의 분류표로 따로 기록하고, 공식 사이트 쪽 장애는 우리 테스트 실패로 치지 않는다(K1). 공식 사이트 안에서의 업무 완료는 요구하지 않는다 |

- **도움:** 진행자가 화면 위치, 용어 뜻, 누를 곳을 알려 주는 것
- **핵심 막힘:** 잘못된 서비스 선택, 이용 조건 오해(대상·비용·인증), 공식 이동 실패.
  - 발견하면 고친 뒤 같은 과업으로 다시 확인한다. 다시 확인할 때는 그 과업을 해 보지 않은 참가자를 먼저 쓰고, 어려우면 같은 참가자가 하되 기록에 표시한다.
  - 해결되지 않으면 커뮤니티 공개를 보류한다.
- **과업 뒤 질문(K4):** 답이 정답지와 다르면 핵심 막힘(조건 오해)으로 센다. 정답지는 과업별로 미리 만들고, 비용이 `unknown`이면 "공식 확인 필요"가 정답이다.
  1. 조건: "이 서비스를 누가, 얼마에, 어떻게 인증해서 쓸 수 있나?"
  2. 다음 행동: "공식 사이트에서 이제 무엇을 해야 하나?"
  3. 비공식 인지: "이 사이트는 도서관이 운영하나?" (정답: 아니오)
- **과업 배정:** 참가자 유형에 맞는 과업을 맡긴다. 대학원생 참가자가 없으면 A7~A9는 학부생이 대신하고 기록에 표시한다(기본값, REVIEW-2 Q2).

## 2. 바꾸면 안 되는 조건 (범위 제한)

1. **로그인·회원가입·개인정보 수집이 없다.** 사이트 안 입력은 검색어뿐이다. 오류 제보는 외부 구글 폼으로만 받는다(D9).
2. **비공식 사이트임을 숨기지 않는다.** 학교 로고나 공식 사이트로 착각할 만한 표현을 쓰지 않는다. 실제 이용은 언제나 공식 서비스로 보낸다.
3. **확인하지 않은 사실을 단정하지 않는다.** 무료, 이용 가능, 구독 중, 만료일을 추측해서 쓰지 않는다. 다시 확인하려 했는데 확인하지 못한 것은 "미확인"이라고 쓴다.
4. **대출·예약·신청을 대신하지 않는다.** 실시간 좌석이나 운영 상태를 보여 주는 척하지 않는다.
5. **정적 사이트를 유지한다(D5).** 빌드 도구·프레임워크·ES 모듈·fetch를 쓰지 않는다. 일반 `<script>` 파일만 쓴다.
   - file://과 배포 주소에서 공통으로 보장하는 것: 검색, 필터, 상세 열기.
   - **주소(#) 상태 복원과 뒤로가기는 ②부터 보장한다(D7, D15).**
   - 공유 링크는 배포 주소 기준으로 만든다. file://에서 열었더라도 "링크 복사"는 배포 주소 + # 상태를 준다.
6. **편집 원본은 `data/` 아래 JSON 파일(종류별)뿐이다.** `data.js`는 생성 결과물이며 직접 고치지 않는다. 화면 코드 안의 내용 데이터(`relatedMap`, `bookCases`)도 원본으로 옮긴다.
7. **자료와 메뉴를 잃지 않는다.** 기존 전자정보원 98개·공식 메뉴 89개는 ID 기준으로 모두 어딘가에서 찾을 수 있어야 한다. 가이드(v2의 47개 + ①에서 추가한 가이드)는 이전·통합·삭제 내역을 이유와 함께 남긴다. 틀린 정보와 중복 문구까지 남기라는 뜻은 아니다.
8. **`_비공개/`는 커밋하지 않는다.**
9. **push 전에는 검사 순서를 통과한다(D6, K17, D16).** 작업 트리가 깨끗한지 확인(`git status --porcelain`이 비어 있음) → 데이터 생성 → 생성물이 커밋된 상태와 같은지 확인(`git diff --exit-code data.js`) → 데이터 검사 → Playwright 테스트 → `_비공개/` 제외 확인 → push. 테스트한 파일이 push할 커밋에 들어 있어야 한다. 배포를 시작한 뒤에는 push할 때마다 **배포본이 방금 push한 버전인지 확인한 다음** 배포 주소에서도 테스트를 돌린다.
10. **데이터와 주소(#) 값을 모두 믿지 않는다.** 화면에 넣는 값은 이스케이프한다. 주소에서 온 id·필터 값은 허용 목록과 존재 여부를 확인한 뒤에만 쓰고, 검색어 `q`는 안전한 텍스트로만 표시한다(K14). 링크는 https만 연다.

## 3. 범위와 단계 (D7)

### ① 공개 전 필수 → 끝나면 조용히 배포

①은 **지금 데이터 구조를 유지한 채** 틀린 정보와 불편을 고친다. 데이터 모델 전환은 ②에서 한다.
JSON 추출을 ①에 둔 이유: ①에서 데이터를 고쳐야 하는데, 생성물(data.js)을 직접 고친 뒤 나중에 옮기면 같은 수정을 두 번 하게 되고 2장 6번과도 어긋난다. 그래서 **구조는 바꾸지 않고 옮기기만** 한다.

**주소 값 규칙**

- 공식 사이트 기준 주소는 `https://lib.jejunu.ac.kr/`이다. 공식 링크 비교는 `#` 뒤까지 포함한 전체 주소로 한다(K1).
- 파라미터마다 허용값 목록이 있다. 기본값은 주소에서 생략한다.
- id와 필터 값은 허용 목록과 존재 여부를 확인한다. 검색어 `q`는 허용 목록 없이 안전한 텍스트로만 쓴다(K14).
- 모르는 파라미터나 허용 밖 값은 무시하고, 주소를 정리해 replace한다.
- 모르는 id는 그 종류의 목록 화면으로 **replace**하고 "찾을 수 없는 안내" 문구를 보여 준다(K13).
- 합쳐진 가이드의 옛 id는 이전 내역을 따라 새 카드로 replace한다. 삭제된 id는 이유와 함께 안내한다.
- 테스트에서 주소를 비교할 때는 "경로 + 디코딩한 파라미터"로 비교한다.

**기록과 뒤로가기 규칙 (H7, K13)**

- **화면(경로)이 바뀌면 push, 같은 화면 안의 파라미터 변경은 replace한다.**
  - 검색 화면에 처음 들어가는 입력은 화면이 바뀌는 것이므로 push한다. 이후 입력·필터 변경은 짧은 지연 뒤 replace한다.
  - push하기 전에는 대기 중인 replace를 먼저 실행한다. 한글 조합이 끝난 값만 주소에 반영한다.
- 검색어가 있는 상태에서 상황 분류를 바꾸면 `#/search?q=…&cat=…`로 간다(같은 검색 화면 안의 변경이므로 replace). 검색어가 없으면 `#/category/<id>`로 간다(push).
- 사이트 안에서 연 상세를 닫으면 바로 전 상태로 돌아간다(history.back).
- 공유 링크로 바로 들어온 상세를 닫으면 그 종류의 목록 화면으로 replace한다(할 일 → 홈, 자료 → 자료 찾기).
- 브라우저 뒤로가기는 기본 기록을 따른다(직접 들어왔다면 사이트 밖으로 나가도 정상).
- 상세를 대화상자로 둘지 별도 화면으로 바꿀지는 PLAN에서 정하되, 위 규칙은 어느 쪽이든 지킨다.

**그 밖의 화면 규칙**

- 모바일: 검색과 주요 메뉴가 위에 계속 보인다. 카드는 한 열. 누르는 영역 44px 이상.
- 화면 문구는 부록 D 용어표를 따른다.
- 나중에 카드별 정적 페이지를 만들 때 `#/task/<id>`를 `/task/<id>.html`로 옮길 수 있게 id는 영문 소문자·숫자·하이픈만 쓴다(D10).

| `id` | 영문 소문자·숫자·하이픈. 기존 가이드 id를 되도록 유지 |
| `title` | 행동형 제목 ("팀플할 공간 예약하기") |
| `question` | 학생 말투 질문 |
| `category` | 상황 분류 6개 중 하나 |
| `levels` | 학부/대학원 필터용. `["undergrad","grad"]` 중 해당하는 것. 기본은 둘 다 |
| `eligibility` | 이용 자격 목록. 각 항목 `{anyOf: [code…], text, source, checkedAt}`. **항목 안의 code는 하나만 맞으면 되고(OR), 항목끼리는 모두 충족해야 한다(AND).** 예: 그룹스터디룸 = `[{anyOf:["enrolled","staff"], text:"재학생·교직원"}]`. code 예: `enrolled`(재학생), `staff`, `disabled`, `member`(도서관 회원). 비어 있으면 "자격 제한 정보 없음 — 공식 안내 확인" |
| `cost` | `{type, text, source, checkedAt}`. type: `free`(무료가 공식 안내로 확인됨) / `paid` / `partial`(일부 유료·지원 한도) / `unknown` |
| `conditions` | 그 밖의 변동 사실 `{kind?, text, source, checkedAt, validFrom?, validTo?}`. 인증 절차·예외는 `kind:"auth"`로 둔다(K7). `validTo`가 지나면 숨기지 않고 "적용 기간 지남 — 공식 확인"으로 표시한다(K19) |
| `location` | `[{text, source, checkedAt}]`. 공간·기기 서비스만. 장소가 여러 곳이면 모두 적는다. 출처가 없으면 넣지 않음 |
| `summary` | 목록 카드의 짧은 설명 |
| `steps` | `{text, verified, source, checkedAt}`(K6). verified: `public`(공개 안내로 확인, 출처·확인일 필수) / `unverified-login`(로그인 뒤 화면 미확인, 들어가는 지점까지의 출처) / `v2`(v2 내용을 옮김, 개별 확인 전. 출처는 v2 레코드의 source)(K5) |
| `official` | 대표 공식 링크 `{label, url, kind, findHint?}`. kind: `page`(해당 페이지) / `list`(목록 첫 화면). **kind가 `list`면 `findHint`(찾을 이름과 방법) 필수**(K7) |
| `keywords` | 검색용 단어(공통 주의 문구 넣지 않음) |
| `featured` | 홈 대표 카드 여부 |
| `reviewBasis` | `reviewed`(이번에 직접 검토) / `v2`(v2에서 옮기기만 함). `v2` 카드는 상세 맨 아래에 "v2 자료 기준(2026-10-12) · 개별 재확인 전"으로 표시하고, 확인일 경고도 카드당 1건으로 묶는다(K5) |
| `reviewedAt` | 카드 전체를 실제로 검토한 날짜. **옮기기만 했을 때는 바꾸지 않는다.** 개별 변동 사실은 각자의 `checkedAt`을 옆에 표시 |

**D12 범위의 필수 출처 (K6):** 대표 카드와 자주 바뀌는 사실에서 다음 값은 출처·확인일이 필수이고 `v2`일 수 없다.

| 필드 | 필수 조건 |
|---|---|
| `cost` | `type`이 `unknown`이 아닐 때 |
| `eligibility` | 항목이 있을 때. 빈 목록은 출처 없이 허용 |
| `conditions`, `location` | 항상 |
| 공지 | 항상 |
| `steps` | 대표 카드에서는 `public` 또는 `unverified-login`만 허용 |

### 자료 (resource)

- 현재 필드를 유지한다. 98개에 공통인 주의·단계 문구는 화면 상수로 옮기고 검색 대상에서 뺀다.
- `aliases`: 검증된 약칭·한글 표기·공식 원문 표기(예: "JSTOR Collection" → "JSTOR", "제이스토어"; 공식 원문 오타 "Sage Premire" → 바른 철자). 정확 이름 일치에 쓴다. 다른 자료·메뉴의 이름이나 별칭과 겹치면 데이터 검사 오류.
- `status` (값마다 필수 필드가 있다):

| 값 | 뜻 | 필수 필드 |
|---|---|---|
| `listed` | 목록에 등재(이용 범위 확인 필요) | — |
| `open` | 공개자료로 안내 | — |
| `trial` | 시범서비스, 기간이 연·월·일까지 확인됨 | `trialFrom`, `trialTo` |
| `trial-period-unclear` | 시범서비스, 기간 표기에 연도가 없는 등 확인 불가 | `trialPeriodText`(원문). 날짜를 추측하지 않는다 |
| `ended` | 출처로 종료가 확인됨 | `endedSource` |

- 화면: `trial`은 `trialTo`가 지나면 "시범기간 종료 — 현재 제공 여부 미확인"으로 표시한다. 자료는 숨기지 않는다.
- 배지: `listed`는 배지를 달지 않는다(98개 중 대부분이라 정보가 없음). `open`·`trial`·`trial-period-unclear`·`ended`만 표시한다(M5).
- `conditions`: 할 일 카드와 같은 형식. WSJ(학내 IP에서만 등록), NICE(초대링크 필요)처럼 인증 예외는 `kind:"auth"`로 둔다(K7).
- `official`: 할 일 카드와 같은 형식. 자료는 대부분 목록형이므로 `findHint`(예: "목록에서 'JSTOR Collection' 검색")가 필수다.
- `accessType`: `status`와 의미를 대조해, 겹치면 status에서 만들어 내고 편집 원본에서는 뺀다(P2-01).
- `useFor`: "과제에서 이렇게 쓴다" 한 줄. ②에서는 대표 카드에 붙는 자료부터 채운다.

### 공식 메뉴 (menu)

현재 필드를 유지하고 `aliases`(선택), `needsLogin`(로그인 화면으로 전환되는 메뉴, 링크 점검 결과로 채움)과 생성되는 `attachedTo`를 더한다. 89개에 공통인 질문·주의 문구는 화면 상수로 옮긴다.

### 공지 (notice)

`{id, text, link, source, checkedAt, startsOn, endsOn, taskIds}`. `taskIds`의 카드가 실제로 있는지 데이터 검사로 확인한다.

### 날짜 규칙

- 저장 형식은 `YYYY-MM-DD`이다.
- 기준은 **보는 사람 기기의 오늘 날짜**이고, 시작일과 종료일 당일을 포함한다. 문자열 비교로 판정한다.
  - 오늘 날짜는 기기의 로컬 연·월·일로 만든다.
  - `new Date('YYYY-MM-DD')`는 UTC로 해석되므로 쓰지 않는다. `toISOString()`도 한국 시간 0~9시에 전날이 되므로 쓰지 않는다.
- 테스트는 날짜와 시간대를 고정해서 돌린다(Playwright 시계 고정, `timezone_id` 고정). 시간이 지나도 깨지지 않게 시험기간 같은 공지는 **테스트용 공지(픽스처)**로 검사한다(K2).
- 데이터 검사: 날짜 형식, 시작일 ≤ 종료일, 상태별 필수 필드.
- 운영 점검일: data.js 최상위에 운영자가 월 점검 때 기록하는 `lastReviewedAt`을 둔다. 데이터를 다시 만든 날이 아니라 **다시 확인한 날**이다(K20).

### 동의어 (synonyms)

- 저장 방식: `[["조별과제","팀플","팀프로젝트","조모임"], ["프린터","프린트","인쇄"], …]`처럼 **같은 뜻 묶음**으로 저장한다. 묶음 안에서는 양방향이다.
- 여러 단어로 된 동의어는 공백을 지운 형태로 저장한다.
- 한 단어가 여러 묶음에 들어가면 데이터 검사 오류로 처리한다.
- 검증된 묶음만 넣는다. 0건이 나온 검색어라고 해서 도서관이 그 서비스를 제공한다고 가정하고 추가하지 않는다.

### "무료·무제한" 처리 (K10)

- **검색:** 검색어 단어가 "무료" 또는 "무제한"이면 다른 필드와 비교하지 않고, 생성 키워드로만 일치를 본다.
  - 생성 키워드는 `cost.type`이 `free`이고 출처가 있는 카드에만 생성 스크립트가 "무료"를 붙인 것이다.
  - ①에는 이 속성이 없으므로 "무료" 검색은 0건이다.
- **데이터 검사:** 편집 원본 JSON에서 **우리가 쓰는 주장 필드**(제목·이름·키워드·질문·요약)에 "무료·무제한"이 있으면 오류다.
  - 조건·주의·공식 원문(officialDescription)은 사실을 옮긴 문장일 수 있어 허용한다.
  - 예: 공식 원문 er-098의 "무제한", 에디티지의 "무료는 일부 부가서비스에 해당".
- 비용 설명 문장(cost의 text)은 검색 대상에서 뺀다.

## 6. 검색 규칙

| 순서 | 규칙 | 단계 |
|---|---|---|
| 1 | **단어 나누기:** 검색어를 공백으로 나눈다 | ① |
| 2 | **정규화(단어마다):** NFKC → 소문자 → 공백·문장부호·기호 제거. 비교 대상 필드도 같은 방식으로 정규화한다("영어논문" = "영어 논문") | ① |
| 3 | **빈 단어 처리:** 정규화 뒤 빈 단어는 버린다. 모든 단어가 비면 결과 대신 "검색어를 입력하세요" 안내를 보여 준다 | ① |
| 4 | **결합:** 모든 단어가 맞아야 결과에 나온다(AND). 단어마다 필드를 하나씩 따로 비교하고, 필드를 이어 붙여 비교하지 않는다. 단어끼리는 서로 다른 필드에서 맞아도 된다 | ① |
| 5 | **동의어:** 단어마다 그 단어가 속한 동의어 묶음 전체를 후보로 삼아, 하나라도 맞으면 일치(OR). 이어지는 단어들을 붙인 형태가 동의어와 같으면 한 단위로 묶고, 겹치면 더 긴 묶음을 먼저 쓴다(예: "팀 프로젝트 공간" → [팀프로젝트][공간]) | ② |
| 6 | **엄격 AND 보완:** "할·곳·찾기" 같은 말 때문에 0건이 되지 않게, 제한된 불용어 목록(데이터) 또는 질문·키워드·동의어 보강 중 하나를 PLAN에서 골라 검색어 표로 검증한다 | ② |
| 7 | **점수:** 아래 검색 필드 표의 가중치. 단어마다 가장 잘 맞은 필드의 가중치를 더한다. 검색어 전체가 자료·메뉴의 이름 또는 별칭과 정확히 같으면 +100 | ② (①은 최소 정렬: 이름·제목에 검색어가 있으면 먼저) |
| 8 | **구획과 순서:** 할 일 / 자료 / 공식 바로가기. 정확한 이름·별칭 일치가 있는 구획을 맨 앞에, 없으면 할 일 구획이 맨 앞. 구획 안에서는 점수 → 대표 카드 → 제목 순 | ② |
| 9 | **같은 서비스 묶기(K12):** 카드에 붙은 메뉴(`task.menus`)와 `task.represents`의 자료·메뉴의 이름·별칭은 **그 카드의 검색 필드**(가중치 3)로 친다. 일치하면 그 카드 안에 "일치: 자료/공식 메뉴 '…'"로 보이고, 메뉴가 여러 카드에 붙어 있으면 각 카드에 모두 보인다. 그 자료·메뉴는 독립 결과로 다시 나오지 않는다. 단, 검색어가 그 이름·별칭과 정확히 같으면 자료·공식 바로가기 구획에도 나온다. "한 번만"은 독립 결과 항목 기준이다. 링크 주소가 같다는 이유로 합치지 않는다 | ② |
| 10 | **0건 처리:** ① 필터가 걸려 있으면 "필터를 풀면 N건"과 해제 버튼. ② 그래도 0건이면 일부 단어만 맞는 결과를 "일부 단어 일치"로(일치한 단어 수 → 점수 순) 보여 주고, **결과마다 맞지 않은 단어를 표시**한다(예: "'무료'는 일치하지 않음")(K11). ③ 그래도 0건이면 이유 안내, 공식 문의 링크, 제보 링크(검색어 미리 채움). 도서관에 없는 서비스를 지어내지 않는다 | ①(필터 안내·제보 링크), ②(일부 일치) |

### 검색 필드 표

**② (새 모델)**

| 종류 | 가중치 5 | 3 | 2 | 1 | 검색하지 않음 |
|---|---|---|---|---|---|
| 할 일 | 제목 | 키워드·동의어, 붙은 메뉴·represents의 이름·별칭 | 질문·요약 | 단계·조건·위치 | 비용 설명, 공통 문장 |
| 자료 | 이름·별칭 | 키워드 | 설명·용도·분야 | 공식 원문 설명 | 비용 설명, 공통 주의·단계 문장 |
| 공식 메뉴 | 이름·별칭 | 메뉴 경로(분류·하위 분류) | 설명 | — | 공통 질문·주의 문장 |

**① (v2 필드 이름, K9)**

| 종류 | 검색하는 필드 | 검색하지 않음 |
|---|---|---|
| 가이드 | name, question, description, keywords, 고유 caution, steps | channel, login, cost, audience, source, materials, ① 보조 필드(facts·eligibilityNote·costNote) |
| 자료 | name, description, officialDescription, keywords, subject, sourceType, 고유 caution, 고유 steps | 위와 같음 + 공통 caution·steps |
| 메뉴 | name, description, keywords, menuGroup, menuSubgroup, 고유 caution | 공통 question·caution·steps, 키워드 끝의 "공식 메뉴" |

- **공통 문장 빼기:** 화면 상수 목록에 있는 문장과 **똑같은 문장이나 배열 원소**만 색인에서 뺀다. 주의 문장과 단계 문장 모두 해당한다.
- ①의 정렬: 이름·제목에 검색어가 들어 있는 항목을 먼저, 그다음은 기존 순서.
- 정규화 규칙은 화면 코드(JS)와 검사 스크립트(Python) 양쪽에 있다. 둘이 같은 결과를 내는지 `normalize-cases.json`(입력 → 기대 출력)으로 양쪽에서 검사한다(K16).

## 부록 E. 필드 전환표 (① → ②)

**가이드 → 할 일 카드**

| ① 필드 | ② 필드 | 규칙 |
|---|---|---|
| `name` | `title` | 행동형 제목으로 다시 씀(대표 카드). 나머지는 그대로 두고 ③에서 정리 |
| `description` | `summary` | 그대로 |
| `facts[]` | `conditions[]` 또는 `eligibility`·`cost`·`location` | 출처·확인일을 그대로 옮김. `kind`가 `location`이면 `location`, `auth`면 `conditions[]`(`kind:"auth"`), `hours`나 없음이면 `conditions[]`. 옮긴 뒤 ① 필드 제거 |
| `eligibilityNote` | `eligibility` | 구조화. 문구는 `text`로 |
| `costNote` | `cost` | type 판정은 출처가 있을 때만 `free`/`paid`/`partial`, 아니면 `unknown` |
| `audience`(all/grad) | `levels` | grad → `["grad"]`, all → 둘 다 |
| `caution`(고유 부분) | `conditions[]` | 공통 문구는 화면 상수로 |
| `channel` | `steps` | 값 표기 통일 |
| `login` | `conditions[]`(`kind:"auth"`) | 자격(`eligibility`)으로 옮기지 않는다(K7) |
| `steps`(문자열) | `steps[{text, verified, source, checkedAt}]` | 대표 카드는 다시 확인해 `public`/`unverified-login`. 나머지는 `verified:"v2"`, source는 레코드의 source(K5) |
| `source`, `findHint`(① 보조 필드) | `official{url, kind, findHint?}` | 목록 주소면 kind=list와 findHint. ①의 `findHint`가 있으면 그대로 옮김 |
| `checkedAt`(234개 모두 같은 날짜) | 카드의 `reviewBasis:"v2"` | 사실마다 넣지 않는다. 대표 카드는 다시 확인한 날짜를 사실별 `checkedAt`과 `reviewedAt`에 넣음(K5) |

**자료 (K7)**

| ① 필드 | ② 필드 | 규칙 |
|---|---|---|
| `facts[]`·`eligibilityNote`·`costNote` | `conditions[]`(인증 예외는 `kind:"auth"`) | 출처·확인일을 그대로 옮김. ①의 `kind:"auth"`는 그대로 |
| `accessType` | `status`에서 생성 | 의미 대조 뒤 결정(이용 범위 확인 → listed, 공개자료 안내 → open, 시범서비스 → trial 또는 trial-period-unclear) |
| `source` | `official{url, kind:"list", findHint}` | findHint 필수 |
| `caution`·`steps`(공통 문장) | 화면 상수 | 고유 문장만 `conditions`로 |
