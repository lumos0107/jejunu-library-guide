# v3 PRD · 기능정의서 (초안 2)

상태: 초안 3. GPT 1차 검토(18개 지적) 반영 → GPT 확인 검토(일부 반영 7개 + 새 문제 4개) 반영 → 사용자 검토 뒤 확정한다.
근거: [DECISIONS.md](DECISIONS.md)(D1~D11), [../AUDIT-2026-10-13.md](../AUDIT-2026-10-13.md).

## 1. 목적

제주대학교 학생이 도서관 서비스 이름을 몰라도 **지금 하려는 일**에서 출발해 쓸 수 있는 서비스를 찾고, 이용 조건을 이해한 뒤, 공식 서비스로 정확하게 이동하게 한다.

### 대상

- 도서관을 거의 안 써 본 학부생
- 과제·발표 자료를 찾는 학부생
- 논문을 쓰는 대학원생
- 자료 이름(예: JSTOR)을 이미 알고 쓰는 곳만 찾는 학생

### 성공 기준

| 기준 | 측정 방법 |
|---|---|
| 대표 과업을 **4번의 행동 안에** 끝낸다. 행동 = 홈에서 시작해 클릭 1회 또는 검색어 입력·제출 1회. 끝 = 정답 상세의 공식 버튼을 눌러 **올바른 공식 주소**가 새 탭으로 열리는 것(공식 버튼 누르기도 행동 1회로 셈) | Playwright 과업 테스트(데스크톱 1440×900, 모바일 390×844). 열린 주소가 과업별 기대 주소와 같은지 확인 |
| 학생이 쓰는 말로 검색하면 정답이 **결과 화면 첫 구획의 상위 3개** 안에 나온다 | 6장 검색어 목록 테스트 |
| 알려진 틀린 정보·단정 표현이 0건이다 | AUDIT 1장 목록 대조 + 데이터 검사 |
| 기존 전자정보원 98개·공식 메뉴 89개의 **ID가 하나도 빠지지 않는다** | 기존 ID 목록과 대조하는 데이터 검사 |
| 모바일 첫 화면(390×844, 스크롤 전)에 검색창이 보이고, 스크롤한 뒤에도 한 번의 행동으로 검색할 수 있다 | Playwright |
| 대표 과업을 학생이 도움 없이 끝낸다 | 학생 사용성 테스트(D8) 기록 |

## 2. 바꾸면 안 되는 조건 (범위 제한)

1. **로그인·회원가입·개인정보 수집이 없다.** 사이트 안 입력은 검색어뿐이다. 오류 제보는 외부 구글 폼으로만 받는다(D9).
2. **비공식 사이트임을 숨기지 않는다.** 학교 로고나 공식 사이트로 착각할 만한 표현을 쓰지 않는다. 실제 이용은 언제나 공식 서비스로 보낸다.
3. **확인하지 않은 사실을 단정하지 않는다.** 무료, 이용 가능, 구독 중, 만료일을 추측해서 쓰지 않는다. 확인 못 한 것은 "미확인"이라고 쓴다.
4. **대출·예약·신청을 대신하지 않는다.** 실시간 좌석이나 운영 상태를 보여 주는 척하지 않는다.
5. **정적 사이트를 유지한다(D5).** 빌드 도구·프레임워크·ES 모듈·fetch를 쓰지 않는다. 일반 `<script>` 파일만 쓴다.
   - file://과 배포 주소에서 **공통으로 보장하는 것:** 검색, 필터, 상세 열기, 주소(#) 상태 복원, 뒤로가기.
   - **공유 링크는 배포 주소 기준으로 만든다.** file://에서 열었더라도 "링크 복사"는 배포 주소 + # 상태를 준다.
6. **편집 원본은 `data/` 아래 JSON 파일뿐이다.** 파일은 종류별로 나눈다. `data.js`는 생성 결과물이며 직접 고치지 않는다. 화면 코드 안에 있던 내용 데이터(관련 안내 `relatedMap`, 책 상황 `bookCases`)도 원본으로 옮긴다.
7. **자료와 메뉴를 잃지 않는다.** 기존 전자정보원 98개·공식 메뉴 89개는 ID 기준으로 모두 어딘가에서 찾을 수 있어야 한다. 가이드 47개는 이전·통합·삭제 내역을 이유와 함께 남긴다. 틀린 정보와 중복 문구까지 남기라는 뜻은 아니다.
8. **`_비공개/`는 커밋하지 않는다.**
9. **push 전에는 검사 순서를 통과한다(D6).** 데이터 생성 → 데이터 검사 → Playwright 테스트 → `_비공개/` 제외 확인. 배포를 시작한 뒤에는 push할 때마다 배포 주소에서도 테스트를 돌린다.

## 3. 범위와 단계 (D7)

### ① 공개 전 필수 → 끝나면 조용히 배포

①은 **지금 데이터 구조를 유지한 채** 틀린 정보와 불편을 고친다. 데이터 모델 전환은 ②에서 한다.
JSON 추출을 ①에 둔 이유: ①에서 데이터를 고쳐야 하는데, 생성물(data.js)을 직접 고친 뒤 나중에 옮기면 같은 수정을 두 번 하게 되고 2장 6번 조건과도 어긋난다. 그래서 **구조는 바꾸지 않고 옮기기만** 한다.

| ID | 기능 | 완료 조건 |
|---|---|---|
| P1-01 | **회귀 테스트 먼저 확보:** QA-v2 시나리오와 지난 Playwright 확인 35개 항목을 자동 테스트로 만든다 | 현재 v2에서 전부 통과 |
| P1-02 | **코드 포맷 정리:** 압축된 app.js·styles.css를 읽기 좋게 푼다. 파일 분리는 최소로(데이터 / 화면 코드 / 스타일 정도). 일반 스크립트의 로딩 순서와 공통 전역 객체를 문서로 남긴다 | P1-01 테스트가 그대로 통과 |
| P1-03 | **JSON 추출:** 현재 구조 그대로 종류별 JSON(`data/`)으로 옮기고 `relatedMap`·`bookCases`도 포함한다. `tools/build_data.py`가 data.js를 만든다 | 일회성 검사 `tools/extract_v2.py --verify`: JSON에서 만든 데이터가 추출 전 data.js·app.js의 내용 데이터와 같음. 이후로는 `build_data.py --check`(생성물 일치)로 유지 |
| P1-04 | **데이터 검사:** ID 고유, 연결 대상 존재, 모든 외부 링크 https, 필수 필드, 기존 자료·메뉴 ID 목록 대조. 화면 코드에서 속성값(`data-open` 등)과 링크 주소를 안전하게 넣는지 검사 | 한 명령으로 실행, 실패 시 종료 코드 1 |
| P1-05 | **틀린 정보 수정:** 시험기간 24시간 개방, `remote`·`print` 단정 표현, 키워드의 "무료·무제한", 성격이 다른 자료에 붙은 주의 문구. 이번에 고치는 시간·요금·대상 같은 **변동 사실에는 출처와 확인일**을 붙인다. ①에서는 기존 레코드에 보조 필드 `facts: [{text, source, checkedAt}]` 하나만 더한다(기존 필드는 그대로) | AUDIT 1장 항목 모두 처리, 고친 변동 사실에 출처·확인일 |
| P1-06 | **최소 공지 기능:** 시험기간 24시간 개방을 기간(시작일·종료일)·출처·확인일과 함께 공지로 보여 주고, 기간 밖에서는 자동으로 숨긴다 | 기간 안·밖 날짜로 테스트 |
| P1-07 | **이용 조건 표시:** 목록 카드에 핵심 대상·비용 조건을, 상세 위쪽에 예외(재학생 한정, 장애인 대상, 유료 협약가, 인증 예외 등)를 보여 준다. 자료 상세의 인증 예외도 포함. ①에서는 짧은 문구 보조 필드 `eligibilityNote`·`costNote`를 더하고, 구조화된 `eligibility`·`cost`는 ②에서 도입한다 | 그룹스터디룸·메이커·사물함·책나래·WSJ·NICE 조건이 정확히 보임 |
| P1-08 | **검색 기본 정비:** 공통 주의·단계 문구와 비용 설명을 검색 대상에서 뺀다. 검색어를 단어로 나눈 뒤 단어마다 정규화(따옴표·문장부호 무시)하고, 필드마다 따로 비교해 경계를 넘는 오매칭을 없앤다. **①에는 비용 속성(`cost.type`)이 없으므로**, 검색 대상 필드에서 "무료·무제한"을 모두 빼고 데이터 검사로 다시 들어오지 못하게 막는다 | ①에서 "무료" 검색은 **0건이 정답**. "무료 아님·무료 여부 미확인·유료"가 적힌 항목이 결과에 나오지 않는 재현 테스트. “통계”(둥근 따옴표) = 통계 |
| P1-09 | **필터·검색어 유지:** 상황 탭을 눌러도 검색어 유지. 적용 중인 필터를 결과 위에 보여 주고 하나씩 해제. 숨은 필터 때문에 0건이면 "필터를 풀면 N건"을 보여 준다 | AUDIT 2장 "숨은 필터" 재현이 해결 |

| P1-11 | **상세의 마지막 한 걸음:** 공식 버튼을 상세 위쪽에. 일반 면책은 한 번만. 공식 링크가 목록 첫 화면이면 "목록에서 '자료 이름'을 검색하세요"처럼 찾는 방법을 함께 보여 준다 | 데스크톱·모바일 상세 첫 화면에 공식 버튼 |

| P1-13 | **책 반납 안내 추가:** 공식 공개 안내를 확인해 반납 방법 가이드를 쓴다 | 출처·확인일이 붙은 가이드 1개, "책 반납" 검색 1위 |

| 검색 결과 | `#/search?q=…&level=…` | 구획: 할 일 / 자료 / 공식 바로가기. 적용 중인 필터 표시와 해제. 0건 처리 |
| 할 일 상세 | `#/task/<id>` | 공식 버튼(위) → 이용 조건 → 이용 방법 → 필요한 자료 → 공식 메뉴 위치 → 관련 할 일 → 출처·확인일 |
| 자료 찾기 | `#/resources?subject=…&q=…` | 98개, 분야·제공 표시 필터, 이름 검색 |
| 자료 상세 | `#/resource/<id>` | 공식 설명, 매뉴얼 링크, 붙은 할 일, 공식 목록에서 찾는 방법 |
| 공식 바로가기 | `#/menus?group=…` | 카드에 안 붙은 메뉴를 분류별로, 카드에 붙은 메뉴는 해당 카드로 안내 |

**주소와 뒤로가기 규칙**

- 사이트 안에서 화면이 바뀔 때마다 주소(#)를 바꾸고 기록을 남긴다. 검색어 입력 중에는 기록을 남기지 않고 주소만 갱신한다.
- 사이트 안에서 이동한 뒤 뒤로가기를 누르면 **바로 전 상태(검색어·필터·열린 상세)**로 돌아간다.
- 공유 링크로 상세에 바로 들어온 경우, 상세 뒤에는 홈을 깔아 둔다. 뒤로가기는 브라우저 기본 기록을 따른다(사이트 밖으로 나가도 정상).
- 상세를 닫으면 상세를 열기 전의 주소로 돌아간다. **공유 링크로 바로 들어와 이전 주소가 없으면** 그 종류의 목록 화면으로 간다(할 일 상세 → 홈 `#/`, 자료 상세 → 자료 찾기 `#/resources`).
- 상세를 대화상자로 둘지 별도 화면으로 바꿀지는 PLAN에서 정하되, 위 규칙은 어느 쪽이든 지킨다.
- 모바일: 검색과 주요 메뉴가 위에 계속 보인다. 카드는 한 열. 누르는 영역 44px 이상.
- 나중에 카드별 정적 페이지를 만들 때 `#/task/<id>`를 `/task/<id>.html`로 옮길 수 있게 id는 영문 소문자·숫자·하이픈만 쓴다(D10).

## 5. 데이터 모델 (②에서 전환)

원본: `data/` 아래 종류별 JSON. `tools/build_data.py`가 `data.js`(`window.LIBRARY_GUIDE`)를 만든다.
파일: `categories.json`, `tasks.json`, `resources.json`, `menus.json`, `notices.json`, `synonyms.json`, `book-cases.json`, `migration.json`(가이드 이전 내역).

### 관계는 한쪽에서만 편집한다

| 편집하는 쪽 | 생성되는 반대쪽 |
|---|---|
| `task.resources` (추천 자료 0~3개) | `resource.usedIn` (붙은 할 일) |
| `task.menus` (붙은 공식 메뉴) | `menu.attachedTo` |
| `task.related` (관련 할 일) | 생성하지 않음(한 방향) |
| `task.represents` (이 카드가 곧 그 서비스의 안내인 자료·메뉴. 예: O’Reilly 카드 ↔ O’Reilly 자료) | 검색에서 같은 서비스로 묶는 데 씀(6장 8번) |
| `notice.taskIds` (공지를 함께 보여 줄 카드) | 카드 상세의 공지 목록 |

### 할 일 카드 (task)

| 필드 | 설명 |
|---|---|
| `id` | 영문 소문자·숫자·하이픈. 기존 가이드 id를 되도록 유지 |
| `title` | 행동형 제목 ("팀플할 공간 예약하기") |
| `question` | 학생 말투 질문 |
| `category` | 상황 분류 6개 중 하나 |
| `levels` | 학부/대학원 필터용. `["undergrad","grad"]` 중 해당하는 것. 기본은 둘 다 |
| `eligibility` | 실제 이용 자격 목록. 각 항목은 `{anyOf: [code…], text, source, checkedAt}`. **항목 안의 code는 하나만 맞으면 되고(OR), 항목끼리는 모두 충족해야 한다(AND).** 예: 그룹스터디룸 = `[{anyOf:["enrolled","staff"], text:"재학생·교직원"}]`. code 예: `enrolled`(재학생), `staff`, `disabled`, `member`(도서관 회원). 비어 있으면 "자격 제한 정보 없음 — 공식 안내 확인"으로 표시 |
| `cost` | `{type, text, source, checkedAt}`. type: `free`(무료가 공식 안내로 확인됨) / `paid` / `partial`(일부 유료·지원 한도) / `unknown` |
| `conditions` | 그 밖의 변동 사실 `{text, source, checkedAt, validFrom?, validTo?}` (시간·수량·기간 등) |
| `summary` | 목록 카드의 짧은 설명 |
| `steps` | `{text, verified, sourceRef}`. verified: `public`(공개 안내로 확인) / `unverified-login`(로그인 뒤 화면 미확인). **`public` 단계는 `sourceRef`(확인 근거 URL)가 필수**이고, `unverified-login` 단계는 들어가는 지점까지의 근거를 적는다 |
| `official` | 대표 공식 링크 `{label, url, kind}`. kind: `page`(해당 페이지) / `list`(목록 첫 화면 — 찾는 방법을 함께 표시) |
| `location` | 위치(층·호실), 없으면 생략 |
| `keywords` | 검색용 단어 (공통 주의 문구 넣지 않음) |
| `featured` | 홈 대표 카드 여부 |
| `reviewedAt` | 이 카드 전체를 마지막으로 검토한 날짜(상세 맨 아래 표시). 개별 변동 사실은 각자의 `checkedAt`을 옆에 표시 |

### 자료 (resource)

- 현재 필드를 유지한다. 98개에 똑같이 들어간 공통 주의·단계 문구는 화면 상수로 옮기고 검색 대상에서 뺀다.
- `status`:
  - `listed`: 목록에 등재(이용 범위 확인 필요)
  - `open`: 공개자료로 안내
  - `trial`: 시범서비스, 기간이 연·월·일까지 확인됨(`trialFrom`, `trialTo`)
  - `trial-period-unclear`: 시범서비스, 기간 표기에 연도가 없는 등 확인 불가. 원문 기간 표기(`trialPeriodText`)만 저장하고 날짜를 추측하지 않는다
  - `ended`: 출처로 종료가 확인됨
- 화면: `trial`은 `trialTo`가 지나면 "시범기간 종료 — 현재 제공 여부 미확인"으로 표시한다. 자료 자체는 숨기지 않는다.
- `useFor`: "과제에서 이렇게 쓴다" 한 줄. ②에서는 대표 카드에 붙는 자료부터 채운다.

### 공식 메뉴 (menu)

현재 필드 유지 + 생성되는 `attachedTo`. 89개에 공통인 질문·주의 문구는 화면 상수로 옮긴다.

### 공지 (notice)

`{id, text, link, source, checkedAt, startsOn, endsOn, taskIds}`. 보는 사람의 오늘 날짜가 `startsOn`~`endsOn` 안일 때만 홈과 `taskIds`에 적힌 카드에 보인다. `taskIds`의 카드가 실제로 있는지 데이터 검사로 확인한다.

### 동의어 (synonyms)

`[["조별과제","팀플","팀 프로젝트","조모임"], ["프린터","프린트","인쇄"], …]` 처럼 **같은 뜻 묶음**으로 저장한다(묶음 안에서는 양방향). 검증된 묶음만 넣는다. 0건 검색어라고 해서 도서관이 그 서비스를 제공한다고 가정해 추가하지 않는다.

### "무료" 처리

- 비용 설명 문장은 검색 대상에서 뺀다.
- `cost.type`이 `free`인 카드에만 생성 스크립트가 검색어 "무료"를 붙인다. "무료"라는 단어는 **이 생성 키워드로만** 일치한다.
- 데이터 검사: `cost.type`이 `free`가 아닌데 검색 대상 필드(제목·키워드·질문·요약·단계)에 "무료·무제한"이 있으면 오류로 처리한다.
- ①에서는 이 속성이 아직 없으므로 P1-08 규칙(검색 대상에서 "무료·무제한" 제거, 0건이 정답)을 따른다.

## 6. 검색 규칙 (P1-08 기본, P2-07 고도화)

1. **단어 나누기:** 검색어를 공백으로 나눠 단어 목록을 만든다.
2. **정규화(단어마다):** NFKC → 소문자 → 공백·문장부호·기호 제거. 비교 대상 필드도 같은 방식으로 정규화한다. 그래서 "영어논문"은 "영어 논문"이라고 적힌 필드와도 일치한다.
3. **동의어(②):** 단어마다 그 단어가 속한 동의어 묶음 전체를 후보로 삼는다. 후보 중 하나라도 맞으면 그 단어는 일치(OR). 동의어 묶음은 양방향이다.
   - **여러 단어로 된 동의어**("팀 프로젝트")는 공백을 지운 형태로 저장한다. 검색어에서 이어지는 단어들을 붙인 형태가 동의어와 같으면 그 단어들을 **한 단위**로 묶는다. 겹치면 더 긴 묶음을 먼저 쓴다. 예: "팀 프로젝트 공간" → [팀프로젝트][공간].
4. **결합:** 모든 단어가 일치해야 결과에 나온다(AND). 단어마다 **필드를 하나씩 따로** 비교하고, 필드를 이어 붙여 비교하지 않는다. 단어끼리는 서로 다른 필드에서 맞아도 된다.
5. **점수:** 단어마다 가장 잘 맞은 필드의 가중치를 더한다. 제목·이름 5 / 키워드·동의어 3 / 질문·요약 2 / 단계·조건 1. 검색어 전체가 자료·메뉴 이름과 정확히 같으면 +100.
6. **구획과 순서:** 결과를 할 일 / 자료 / 공식 바로가기 구획으로 나눈다. 정확한 이름 일치가 있는 구획을 맨 앞에 둔다. 없으면 할 일 구획이 맨 앞이다. 구획 안에서는 점수 → 대표 카드 → 제목 순.
7. **메뉴 연결(②):** 카드에 붙은 메뉴가 일치하면 공식 바로가기 구획에 따로 보이지 않고, 그 카드가 할 일 구획에 나오며 "일치: 공식 메뉴 '…' (경로)"를 보여 준다.
8. **같은 서비스 묶기:** "같은 서비스"는 데이터의 관계로만 판단한다.
   - 카드에 붙은 메뉴(`task.menus`)와 카드가 곧 그 안내인 자료·메뉴(`task.represents`)가 일치하면, 따로 보이지 않고 그 카드 결과 안에 "일치: 자료/공식 메뉴 '…'"로 보인다.
   - 단, 검색어가 그 자료·메뉴 이름과 **정확히 같으면** 자료·공식 바로가기 구획에도 보여 준다(5번의 +100, 6번의 구획 순서).
   - 같은 레코드는 한 번만 보인다. 서로 다른 할 일 카드가 같은 서비스를 참조하는 것은 중복이 아니다.
   - 링크 주소가 같다는 이유로 합치지 않는다(전자정보원 다수가 같은 목록 주소를 씀).
9. **0건 처리:** 필터가 걸려 있으면 "필터를 풀면 N건"과 해제 버튼을 먼저 보여 준다. 그래도 0건이면 일부 단어만 맞는 결과를 "일부 단어 일치"로 보여 준다. 도서관에 없는 서비스를 지어내지 않는다.

## 7. 비기능 요구

- **성능** (측정 환경: 로컬 file://, Playwright Chromium, 데스크톱 1440×900, 5회 실행 중앙값)
  - 첫 화면: 페이지 이동 시작(`performance.timeOrigin`)부터 화면 코드가 첫 카드 목록을 그린 직후 남기는 표시(`performance.mark('first-render')`)까지 1초 이내
  - 검색: 입력 이벤트에서 결과 목록 갱신 직후 표시(`performance.mark('search-rendered')`)까지 50ms 이내
- **접근성:** WCAG 2.1 AA 대비, 키보드만으로 모든 기능, 대화상자 포커스 관리, 동작 줄이기 설정 존중.
- **브라우저:** 최신 Chrome·Edge·Safari(iOS)·삼성 인터넷. 2장 5번의 공통 보장 범위를 file://과 https 양쪽에서 테스트한다.
- **크기:** data.js는 현재 313KB를 **목표 예산**으로 둔다. 공통 문구를 줄여 여유를 만들고, 넘으면 이유와 실제 성능을 기록한다.
- **보안:** 데이터에서 온 값은 텍스트·속성 모두 이스케이프한다. 링크 주소는 https만 허용한다.

- 상세를 대화상자로 유지할지 별도 화면으로 바꿀지 (PLAN에서, 4장 주소 규칙은 공통)
- 대표 카드 6~10개 후보: 팀플 공간 예약(`group`), 시험기간 늦게까지 공부(`hours`·`seat`), 프린트·스캔(`print`), 발표용 통계(`stats`), 영어 논문 찾기와 교외접속(`overseas`·`remote`), 참고문헌 정리(`citation`), 표절 검사(`similarity`), 영문 교정(`editage`·`enago`), 학위논문 제출(`thesis-submit`), 책 반납·연장(`loan` + P1-13)
- `eligibility` code 목록의 최종 값 (②에서 실제 데이터를 옮기며 확정)
