# 6차 교차 평가: 디자인(색·글꼴·핵심 화면) — 2026-10-13

배포본을 본 사용자가 "디자인 적인 것도 고려해 봐야함 — 색, 폰트 핵심 디자인등등"이라고 요청했다. 사용자가 정리해 둔 디자인 규칙(색 4~5개, 폰트 하나(Pretendard), 그라데이션·0.3초 이상 애니메이션·UI 이모지 금지, 아이콘은 Tabler·Ionicons·Heroicons에서만, 여백 있는 단순한 화면)을 기준으로 삼았다.

## 방식

- 평가자 4명, 2라운드: GPT-A(디자인 시스템), GPT-B(사용성·화면 위계·모바일), Claude-A(브랜드·첫인상), Claude-B(구현·위험·검증). 같은 공통 자료와 캡처(우리 사이트 데스크톱·모바일 홈, 검색 결과, 상세, 공식 홈)를 봤다.
- 2라운드에서는 서로의 1라운드 의견을 보고 동의·반대를 밝혔다. 의견이 갈린 글꼴 방식은 GPT와 한 번 더 토론했다.
- Claude-B는 저장소 사본으로 실측했다(390×844, Chromium·WebKit, 느린 망 1.6Mbps).

## 지금 디자인의 문제(1라운드 공통)

| 항목 | 지금 | 사용자 규칙 |
|---|---|---|
| 색 | 22가지(변수 7 + 직접 쓴 색 15) | 4~5개 |
| 글꼴 | 시스템 글꼴(윈도우는 맑은 고딕이라 600~760이 모두 700으로 보임) | Pretendard 하나 |
| 글자 크기·굵기 | 21가지·7가지 | 몇 단계 체계 |
| 모바일 첫 화면 | 공지 상자(3건)가 화면의 55%, 검색창이 575px 아래, CLS 0.495(나쁨 기준 0.25) | — |

점수: Claude-A 6/10(첫인상), Claude-B 4/10(유지보수성). GPT는 점수 없이 문제와 값으로 답했다.

### GPT가 직접 서브셋을 받아들인 조건(모두 반영)

1. 실제로 만든 글꼴 기준의 글자 검사: `fonts/glyphs.txt`와 화면 데이터·문구를 대조하고 빠진 글자는 데이터 검사에서 실패(예외 ∙·▣는 명시).
2. 재생성 절차 고정: `tools/build_font.py`에 원본 주소·sha256을 기록.
3. 수정본 이름과 라이선스: 글꼴 이름 GuideSans, `fonts/OFL.txt`와 `fonts/README.md`(출처·수정 사실).
4. 실제 배포 환경 확인: `font-display: swap`과 시스템 대체 글꼴, 배포 확인에 글꼴 파일 포함.

## 사용자가 정할 것

| 항목 | 평가자 의견 |
|---|---|
| 아이콘(상황 6개 + 머리말 검색, Tabler outline) | Claude 2명은 넣자, GPT 2명은 미루자(2:2) → 시안 A(아이콘)·B(없음)를 같이 보여 준다 |
| 색 개수에 투명도(구분선·뒤판)를 셀지 | Claude-A: 사용자 확인 필요 |
| 부드러운 스크롤 | Chromium에서 0.78~0.99초로 0.3초 규칙을 넘는다(Claude-B 실측). GPT-B는 즉시 이동, 다른 평가자는 사용자 결정 |
| ↗ 뜻 정리(밖으로 나가는 링크에만) | 4명 동의하나 손댈 곳이 넓어 2차, 사용자 확인 후 |

## 2차로 미룬 것

반경·간격 토큰 전면 정리와 CSS 구조 정리(값을 바꾸지 않는 커밋으로 따로), 검색 결과 조작부 압축, 공지 짧은 제목(데이터), 상황 카드 모바일 배치 재검토, ↗ 정리, 부드러운 스크롤(결정 뒤).

## 검증(시안 v1, 브랜치 design-proto)

- 자동 테스트: 대비 AA, 44px(펼친 공지 링크 포함), 상세 첫 화면 안 공식 버튼·조건, 모바일 첫 화면 검색창(공지 0~3건), 공지 접기·펼침 유지, 글꼴 요청 1개·320KB 이하, 디자인 규칙 검사(:root 밖 색 0, 글자 크기 토큰, 굵기 3단계, 0.3초 이상 전환·그라데이션 0), 상황 카드 HTML = 데이터, 글꼴 글자 검사.
- 첫 화면 81ms(기준 1,000ms), 검색 0.8ms.
- 비교 캡처: 홈(모바일·데스크톱, 시안 A·B), 공지 0·1·3건·펼침, 상세(그룹스터디룸·er-085), 검색 결과.
